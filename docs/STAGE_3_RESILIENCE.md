## Шкала часов между процессами

`mach_continuous_time()` остаётся источником интервалов, включая сон. Новый `ClockDomain` пытается использовать существование собственного именованного POSIX-семафора как маркер жизни ядра. Имя содержит 24 шестнадцатеричных символа из случайного UUID и не длиннее 31 байта; не содержит идентификатора телефона или пользователя. Один маркер для обеих областей, без App Groups и новых entitlement. Это не общедоступный идентификатор и не средство аналитики.

`Application Support/UniverseSessionV1/clock` исключён из резервных копий и защищён до первого разблокирования. Файл маркера содержит только `version`, `name`, `token`; строгий формат, не более 512 байт. Во время инициализации неблокирующий `flock` исключает конкурирующую запись. В процессе токен кешируется.

Последовательность восстановления:

1. Прочитать и проверить запись; открыть существующий семафор без создания. Если он существует, вернуть сохранённый токен.
2. При отсутствии записи или системного объекта создать новый случайный токен. Сначала записать защищённый staging-файл, синхронизировать, переименовать и синхронизировать каталог.
3. Только после успешной фиксации создать семафор с `O_CREAT | O_EXCL`. При сбое между записью и созданием следующий запуск снова сменит токен. Неоднозначная ошибка записи не создаёт объект.
4. Закрыть дескриптор, сохранив объект до перезагрузки. Обычное завершение приложения и диагностический сброс не вызывают `sem_unlink`.

При `EPERM`, `EACCES`, `ENOSYS` или `ENOTSUP` применяется прежний документированный KERN_BOOTTIME с кешем процесса. Повреждение данных, ошибка диска, блокировка другим владельцем и неожиданные ошибки системных ресурсов блокируют чтение часов; они не превращаются в сброс или обход паузы.

При доступном маркере календарный перевод времени между процессами не меняет шкалу непрерывного таймера. При настоящем reboot, первом переходе со старого `boottime-v1` или запасном режиме ядро использует прежнее ограниченное восстановление по UTC. Ручное изменение даты в этих условиях может изменить остаток. Это не абсолютная защита от изменения времени или переустановки. Физическая доступность API при бесплатной подписи ещё не подтверждена; R08 полностью не закрыт.

Основания: [Apple DTS о маркере через семафор](https://developer.apple.com/forums/thread/110044), [контракт sem_open](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/sem_open.2.html), [изоляция семафоров по Team ID в iOS 26](https://developer.apple.com/documentation/ios-ipados-release-notes/ios-ipados-26-release-notes). Это основания для реализации с проверкой доступности, а не доказательство поведения конкретной подписи на iPhone Air. Запрещённый `kern.bootsessionuuid` не используется.

## Ограниченное ожидание уведомлений

Нативная очередь сохраняет порядок операций. Запрос настроек и добавление уведомления ограничены двумя секундами каждый; ожидание системного диалога разрешения — 60 секундами. Использован одноразовый callback с таймером, а не task group, которая могла бы ждать незавершённую системную операцию. Запоздалое разрешение не сохраняет настройку и не включает напоминания. Повторный callback не возобновляет continuation второй раз.

Если исход добавления неизвестен из-за тайм-аута, запрос отменяется и новые добавления в эту область блокируются. Чтение часов, хранение состояния, отмена и сброс теста продолжают работать. После позднего callback запрос отменяется ещё раз, затем блокировка снимается; следующее восстановление при возврате в приложение может повторить планирование. Пока результат неизвестен, новый корректный запрос не может быть затёрт старым. Если callback вообще не придёт, доставка для этой области останется недоступной в текущем процессе, но таймер не остановится. Отмена ОС не является гарантией от уже произошедшей доставки.

При выключенной настройке уведомлений приложение сразу отменяет запрос и не обращается за системными настройками. ID по-прежнему фиксирован и разделён на обычную и диагностическую области. Текст вопроса и ответ отсутствуют. Английская доставка остаётся выключенной до утверждения текста.

## Автоматические проверки и границы

`mobile/tool/run_native_safety.sh` компилирует тот же Swift/C код без Flutter. Проверяет порядок фиксации, ошибки записи до/после commit, прерывание перед созданием, повторное открытие, исчезновение объекта, резервный путь при запрете, неожиданные ошибки, повреждение записи и блокировку конкурирующего владельца. Реальный Darwin-семафор и файловое хранилище проверяются между отдельными процессами; удаляется только случайный объект собственного теста. Удаление объекта моделирует reboot, не выдаётся за настоящую перезагрузку ОС.

Асинхронные проверки покрывают успешный callback, ошибку, повторный и отсутствующий ответ, позднее добавление, блокировку новых добавлений, независимость областей и повтор после очистки. Эти проверки не доказывают физическую доставку уведомления.
